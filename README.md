# Сервер зображень 2.0 (Image Hosting)

Фінальний проєкт для другого модуля Python University (JavaRush) з підтримкою баз даних PostgreSQL, пагінації та управління контентом.

## 📋 Опис проєкту

Веб-додаток для завантаження, зберігання, перегляду та управління зображеннями. Проєкт створений з метою вивчення та практичного закріплення навичок роботи з Python-бекендом, веб-сервером Nginx, контейнеризацією (Docker, Docker Compose), мережами в Docker, збереженням даних через persistent volumes, системою логування та загальною архітектурою веб-додатків. Додаток дозволяє завантажувати файли (формати `.jpg`, `.png`, `.gif` розміром до 5 МБ) та зберігає їхні метадані у базі даних PostgreSQL.
Користувач може завантажувати картинки (із вказаними обмеженнями: у форматах `.jpg`, `.png`, `.gif` розміром до 5 МБ), після чого метадані зберігаються в базі даних PostgreSQL, а самі файли доступні за прямими посиланнями.

### Основний функціонал версії 2.0:
1. **Завантаження зображень** з перевіркою розміру, формату та валідацією вмісту.
2. **Зберігання метаданих** (назва, оригінальне ім'я, розмір, дата, тип) у **PostgreSQL**.
3. **Каталог зображень (`/images-list`)** з виведенням повної інформації та підтримкою **пагінації** (по 10 елементів на сторінку).
4. **Видалення зображень** (одночасне видалення запису з бази даних та фізичного файлу з диска через маршрут `/delete/<id>`).
5. **Система логування** всіх дій користувача та помилок у файл `app.log`.
6. **Резервне копіювання (бекапи)** бази даних за допомогою вбудованих інструментів PostgreSQL, доступне звернення як через http-api так і скриптом

### 🛠 Технології

- **Backend:** Python 3.10+ (`http.server`, `psycopg`)
- **База даних:** PostgreSQL
- **Обробка зображень:** Pillow
- **Веб-сервер / Проксі:** Nginx
- **Контейнеризація:** Docker та Docker Compose

## 🚀 Інструкція із запуску (Docker Compose)

Для запуск проекту потрібно і достатньо мати встановлені **Docker** та **Docker Compose**. Для автоматизованого клонування проекту потрібен ще **git**

1. Клонуйте репозиторій та перейдіть у папку проєкта:
   git clone <посилання_на_репозиторій>
   cd <папка_проєкту>
   
2. Для збирання та запуску контейнерів у фоновому режимі виконайте з кореня проєкту команду:
    docker compose up \-d \--build

Після успішного запуску веб\-інтерфейс буде доступний через проксі-сервер Nginx за адресою: `http://localhost:8080/`

## Зупинка проєкту:
Зупинка контейнерів зі збереженням даних (стан бази даних та сховище файлів не втрачаються):

docker compose down

Зупинка контейнерів із повним очищенням (видаленням томів/volumes):

docker compose down \--volumes


## Як робити backup
Проєкт має інструменти для створення резервних копій бази даних PostgreSQL кількома способами:

### Варіант А: Через шлях API (HTTP-ендпоінт)
Ви можете ініціювати створення бекапу, надіславши запит на спеціальний маршрут бекапу через браузер або утиліту `curl`:
GET http\://localhost:8080/backup

Додаток виконає внутрішню команду `pg_dump` для бази даних і збереже файл резервної копії у змонтовану директорію бекапів.

### Варіант Б: За допомогою скрипта автоматизації `do_backup.ps1`
Для середовища Windows у проєкті передбачено скрипт `do_backup.ps1`. Запустіть його з PowerShell:

./do\_backup.ps1

Скрипт автоматично виконає підключення до контейнера бази даних, згенерує SQL-дамп поточного стану та збереже його на хост-машину в папку резервних копій.

## Маршрути web-interface
Архітектура додатку побудована навколо проксі-сервера Nginx (порт `8080`), який перенаправляє запити до бекенду на Python (порт `8000`) або віддає статичні файли напряму:

* `GET /` — Головна сторінка веб\-додатка з інтерфейсом для завантаження файлів (підтримує перетягування drag-and-drop та ручний вибір).  
* `POST /upload` — Ендпоінт для обробки та валідації завантажених зображень, збереження їх у сховищі та запису метаданих у PostgreSQL.  
* `GET /images/` (або сторінка перегляду) — Розділ із галереєю зображень, де користувачі можуть переглядати мініатюри, оригінальні назви, розмір файлів, час завантаження, MIME-типи, копіювати прямі посилання, видаляти зображення та переміщуватися між сторінками за допомогою пагінації.  
* `GET /backup` — Системний маршрут для запуску процесу резервного копіювання бази даних.  
* `/images/<filename>` — Статичний маршрут, який обробляється Nginx для швидкої роздачі завантажених файлів безпосередньо з диску.
